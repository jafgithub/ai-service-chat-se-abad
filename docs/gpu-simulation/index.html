What it is doing

    What you are looking at

    Every answer the assistant gives starts by searching your association's own documents. That search happens on our server and involves no model at all. If nothing in your documents is close enough to the question, no answer is written, and the resident is told so. That is the box at the bottom of the diagram, and it is the reason the assistant cannot invent a rule about somebody's home.

    Only when something does match does a model get asked to put it into plain words. That is the only job a model does here, and it is the job the GPU would be doing.

    Why there is a switch at all

    A GPU costs about eighty cents an hour while it is running, and nothing at all while it is stopped. Switch it on before a meeting, and the assistant is answering from hardware we control. Leave it running for a month by accident and it is roughly $580.

    So the machine stops itself. Twenty minutes with no questions and it shuts down, and a second check running outside the machine catches it if it ever hangs. Drag the idle slider above and watch the countdown.

    The part worth trying

    Switch to our own GPU while the machine is off, and keep the questions coming. Residents still get answers, because Gemini quietly picks up the work, and the panel says plainly that it did. Then press wedge the GPU while it is running and watch the same thing happen mid conversation.

    That is the behaviour that matters in front of a room. A demonstration fails when a machine is still booting; this one does not, and nobody watching would know unless we told them. We tell them.

    A simulation, not a live reading. Speeds and latencies are modelled on an NVIDIA L4 running an 8B model, and the clock runs at sixty times real time so an idle timeout is watchable. Nothing on this page connects to the running system.
